# ADR 0002: Runs, a stream of progress, and agents that can act

Status: accepted. Date: 2026-11-01.

## Context

The product promise is that anything an assistant does is visible in the dashboard. After ADR 0001 the Activity Ledger recorded single events, and the REST API and `pilot` CLI could only read. An assistant could look at the data but not act on it, and the dashboard could not show work in progress ("a scan is running, step 3").

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Unit of visible work | An `AgentRun` row (kind, title, actor, status, step count, last step) plus ledger events carrying its `runId` | One short row for lists and cards; the ledger keeps the full story. No foreign key from the ledger, like its other links: the record of an action outlives the thing it acted on. |
| Consistency | Each change to a run and its ledger event commit in one transaction | The counter and the event can never disagree. |
| Retries | `Idempotency-Key` on "start"; finishing again with the same status is a no-op, with a different one is a 409 | Agents retry. A retry must not create a second run or hide a conflict. |
| Stalled runs | Derived, not stored: a RUNNING run quiet for 30 minutes is shown as stalled | An agent that dies cannot tell us. No cleanup job needed yet. |
| Live updates | Server-Sent Events that check the database every 2 seconds and send only when something changed | Works when the worker moves to its own process (Sprint 2); an in-process signal would not. |
| What agents may do over REST | Track an application as a Draft (deduplicated by posting link, posting text through the posting guard), move its status through the existing status machine, and report runs. Nothing sends, submits or deletes. | Keeps hard rule 1: nothing is sent without a click. |
| Agent instructions | `pilot skills export` writes a Claude Code skill or generic instructions, never overwriting without `--force` | Assistants need the commands and the rules in a place they already read. |

## Consequences

- New agent-visible surface: write tokens can now create applications and move their status. Each call is attributed to the token's name in the ledger. The security review must cover token scope, rate limits, and whether an agent may set statuses that mean "I sent it" (SENT and later) without a person's confirmation. It currently can.
- A run is only as honest as the agent reporting it; the dashboard shows what was reported.
- The stream polls the database. Cost is two cheap queries every 2 seconds per open dashboard tab; fine for one user, to be revisited before multi-user.
